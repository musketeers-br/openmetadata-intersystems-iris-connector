The passwords are for throwaway test containers only. Admin credentials can be overridden with
`IRIS_ADMIN_USER` / `IRIS_ADMIN_PASSWORD` (loader and start script); test logins are fixed by the
catalog.

## Cell

`(track, login)`. 9 cells. Name `iris-<tag>-<login>`. A cell is the only thing tests branch on (via
`iris_cell`, see [contracts/test-interface.md](contracts/test-interface.md)).

Validation: `IRIS_LOGIN` must be one of the three logins, or the session errors out
(`pytest.UsageError`). `IRIS_TAG` is free text, used for reporting and for tag-specific expectations
recorded in the gap report.

## Fixture catalog v1

Namespace `USER`. Created by the loader; verified by the self-check. **Additive only**: changes need
the fixture owner's review, and renames or removals need both developers.

### Self-check expectations

The loader fails, naming the item, unless every row of this table holds:

| # | Check | Expected |
|---|---|---|
| C1 | The five objects exist with the exact schema and name case | yes |
| C2 | Column names, order and catalog `DATA_TYPE` per object | as in the Objects table. `DATA_TYPE` values not shown there are recorded from `latest-em` during implementation and must match on every track; a track that differs is a gap entry |
| C3 | Constraints by type and columns (PK, UNIQUE `UqBillingCode`, FK → `Clinic.Patient`) | as listed |
| C4 | Table and column descriptions | as listed |
| C5 | Row counts | 2 · 1 · 1 · 1 |
| C6 | View definition readable and joins `Patient` and `Encounter` | yes |
| C7 | `Scratch`: no tables; the admin can create and drop a probe table | yes |
| C8 | `omd_reader`: logs in, reads all three schemas, gets `SQLCODE -99` on both dictionary tables | yes |
| C9 | `omd_reader_dict`: logs in, reads all three schemas and both dictionary tables | yes |
| C10 | Both readers are refused (`-99`) on INSERT into `Clinic.Patient` and on CREATE TABLE in `Scratch` | yes |
| C11 | `AI.Embedding.Vec` catalog `DATA_TYPE` is `varchar` (GAP-001 reproduces; if a future track reports VECTOR, the check reports it and spec 004 is told) | `varchar` |

State transitions: the loader always goes through `cleanup` (drop view, tables, `Scratch` tables, the
`Scratch` schema and users, tolerating "does not exist") → `create` → `load rows` → `grant` →
`self-check`. A second run gives the same end state.

## Gap entry

| Field | Rule |
|---|---|
| `id` | `GAP-NNN`, sequential, never reused |
| `title` | short, states the behavior |
| `component` | IRIS SQL catalog · class dictionary · official driver · official dialect · dbt-iris · OpenMetadata |

| `workaround` | grant, option, or "none" |
| `upstream` | link to an issue, or "not raised" |

in `INFORMATION_SCHEMA.SCHEMATA`; component IRIS SQL catalog; tracks `latest-em`, `latest-cd`; found in
001; connector behavior decided in 002).
