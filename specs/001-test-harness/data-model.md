## Cell

`(track, login)`. 9 cells. Name `iris-<tag>-<login>`. A cell is the only thing tests branch on (via
`iris_cell`, see [contracts/test-interface.md](contracts/test-interface.md)).

Validation: `IRIS_LOGIN` must be one of the three logins, or the session errors out
(`pytest.UsageError`). `IRIS_TAG` is free text, used for reporting and for tag-specific expectations
recorded in the gap report.

### Self-check expectations

The loader fails, naming the item, unless every row of this table holds:

| # | Check | Expected |
|---|---|---|
| C1 | The six objects (five plus the sentinel `Scratch.Keep`) exist with the exact schema and name case | yes |
| C2 | Column names, order and catalog `DATA_TYPE` per object | as in the Objects table. `DATA_TYPE` values not shown there were recorded from `latest-em` on 2026-11-25 and matched on all three tracks; a track that differs is a gap entry |
| C3 | Constraints by type and columns (PK, UNIQUE `UqBillingCode`, FK → `Clinic.Patient`) | as listed |
| C4 | Table and column descriptions | as listed |
| C5 | Row counts | 2 · 1 · 1 · 1 |
| C6 | View definition readable and joins `Patient` and `Encounter` | yes |
| C7 | `Scratch`: only `Keep`, with 0 rows; `Scratch` is listed in `SCHEMATA`; the admin can create and drop a probe table | yes |
| C8 | `omd_reader`: logs in, reads all three schemas, gets `SQLCODE -99` on both dictionary tables | yes |
| C9 | `omd_reader_dict`: logs in, reads all three schemas and both dictionary tables | yes |
| C10 | Both readers are refused (`-99`) on INSERT into `Clinic.Patient` and on CREATE TABLE in `Scratch` | yes |
| C11 | `AI.Embedding.Vec` catalog `DATA_TYPE` is `varchar` (GAP-001 reproduces; if a future track reports VECTOR, the check reports it and spec 004 is told) | `varchar` |

State transitions: the loader always goes through `cleanup` (drop view, tables, every `Scratch` table
including `Keep`, the `Scratch` schema and users, tolerating "does not exist") → `create` → `load rows` → `grant` →
`self-check`. A second run gives the same end state.

## Gap entry

Written in the format ADR-0013 defines and spec 000 already uses in `GAP-REPORT.md` (GAP-004,
GAP-005): heading `### GAP-NNN — <title>` and the bold labels below, in this order.

| Field | Label in `GAP-REPORT.md` | Rule |
|---|---|---|
| `id`, `title` | heading `### GAP-NNN — <title>` | id sequential, never reused; title short and states the behavior |
| `component` | `Component` | IRIS SQL catalog · class dictionary · official driver · official dialect · dbt-iris · OpenMetadata |
| `tracks` | `IRIS tracks` | the tags that reproduce it (evidence-based; mark untested tags as such) |
| `found_in` | `Found in spec` | spec or spike id |
| `reproduction` | `Reproduction` | copy-paste runnable against the fixture catalog, or "pending <spike>" |
| `expected` / `actual` | `Expected` / `Actual` | one line each |
| `connector_behavior` | `Connector behavior` | what the connector does instead, with ADR reference |
| `workaround` | `User workaround` | grant, option, or "none" |
| `upstream` | `Upstream` | link to an issue, "not raised yet", or "not applicable" when the connector handles the limitation itself and there is nothing to report upstream. An upstream issue (OpenMetadata, InterSystems) is opened only after both developers agree |

### Known entries

Spec 000 wrote GAP-004 and GAP-005. Spec 001 adds the others, in id order, and fills every entry's
tracks from the matrix.

| Id | Title | Component | Connector behavior | Written by |
|---|---|---|---|---|
| GAP-001 | VECTOR columns reported as `varchar` in `INFORMATION_SCHEMA.COLUMNS` | IRIS SQL catalog | enrichment from the class dictionary when readable (ADR-0007) | 001 |
| GAP-002 | VECTOR element type and dimension need `SELECT` on `%Dictionary.CompiledProperty` | class dictionary | one `IRIS-VECTOR-GRANT` warning; cataloged as `VARCHAR` | 001 |
| GAP-003 | Objects invisible to a login cannot be detected by that login | IRIS SQL catalog | documented limitation (ADR-0008); reproduction pending SPIKE-03 (spec 005) | 001 |
| GAP-004 | Dialect reads the server version through the Native API | official dialect 1.0.2 | `server_version_info` preset (ADR-0015) | 000 |
| GAP-005 | Dialect's dictionary-access probe is true for every login | official dialect 1.0.2 | `_dictionary_access` preset (ADR-0015) | 000 |
| GAP-006 | Stray `print(...)` in `get_multi_columns` writes one stdout line per reflected column | official dialect 1.0.2 | none (cosmetic) | 001 |
| GAP-007 | Primary key of a class-defined table reflected with its column repeated (e.g. `['ID','ID',…]`) | official dialect 1.0.2 | none yet; system tables are excluded by default (ADR-0009) | 001 |
| GAP-008 | `VARCHAR(1)` reflected as `CHAR`; `LONGVARCHAR` cataloged as `VARCHAR(1)` | official dialect 1.0.2 (the `LONGVARCHAR` half is OpenMetadata's `ColumnTypeParser`) | the type map uses the raw `DATA_TYPE` (ADR-0006, spec 003) | 001 |
| GAP-009 | A schema without tables is not listed in `INFORMATION_SCHEMA.SCHEMATA` | IRIS SQL catalog | none in the connector; the fixtures keep the sentinel `Scratch.Keep` so `Scratch` stays listed (FR-002) | 001 |

GAP-006 to GAP-008 were found with SPIKE-01 on `latest-em`. `Billing.Patient` is enough for 006;
008 uses `Clinic.Encounter` (`Notes LONGVARCHAR`) and a `VARCHAR(1)` table it creates and drops in
`Scratch`. GAP-007 does not reproduce on a primary key declared in DDL, composite or not (checked as
admin and both readers, with and without dictionary access), so its reproduction reads the system
table `Ens_Util.LookupTable` as admin (research, "Gap reproductions").
